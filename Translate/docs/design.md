# 首版设计与验收

## 从网页到译文

Chrome 扩展使用 Manifest V3。打开扩展弹窗时，`activeTab` 允许扩展访问当前网页。弹窗负责发送操作并显示状态。点击「翻译当前页」后，页面脚本从当前 DOM 读取已加载的正文，记住每段对应的元素。文章、Markdown 和具备正文特征的段落进入对照显示。其他可见英文按原有文字节点翻译。识别时跳过屏幕阅读器专用标签、隐藏或裁剪的元素、代码和可编辑区域。

扩展给每段编号，按页面顺序分批。每批最多 12 段、3200 个字符。超过 3200 字符的段落分片发送，收到完整译文后合并显示。超过 16000 字符的单段会跳过。扩展后台负责把每批文本发给本地服务。

本地服务使用 API Key 通过 HTTPS 请求 DeepSeek，要求模型按段落编号返回 JSON。服务和扩展都会核对返回的编号，避免译文因乱序而放错位置。正文译文以纯文本插入原段落下方。界面翻译只更新原文字节点。先尝试原位对照，再尝试中文和带省略号的中文。每次试排都检查原有空间和行数。显示不下时保留英文，网页原本没有提示时可以通过悬停查看完整译文。

当一批失败时，页面脚本记住失败位置。重试从失败的批次开始，再继续后续批次。若用户恢复网页，页面会移除已插入的译文，并丢弃这次任务后续返回的结果。已发送的 DeepSeek 请求可能仍会完成。

## 本地接口

本地服务监听 `127.0.0.1:8765`，接受 `POST /translate`。扩展向该地址发送 JSON，并附带 `X-Translate-Client: chrome-extension`。服务拒绝普通网页来源和跨域预检。这个请求头用于限制网页访问。能访问该端口的本机程序也可以构造请求。

请求示例：

```json
{"blocks":[{"id":1,"text":"Read the documentation."}]}
```

成功响应示例：

```json
{"translations":[{"id":1,"text":"阅读文档。"}]}
```

失败时返回 HTTP 错误状态和包含 `error` 字段的 JSON。API Key 仅由本地服务读取，扩展发给本地服务的是段落编号和正文。模型请求同样只包含翻译指令、编号和正文。

## 人工验收

1. 用一篇新闻、一篇博客和一篇技术文档各翻译一次。记录点击到首批显示的时间，检查标题和正文下方有没有对应译文。
2. 检查原文链接、代码块和图片。关闭中文译文，再恢复网页，确认译文已经移除。
3. 翻译长文章时关闭再打开扩展弹窗，检查页面是否继续显示新返回的译文。
4. 停止本地服务后开始翻译，确认弹窗提示连接失败。启动服务，再点击「重试翻译」，确认译文正常显示。
5. 翻译有动态内容的文章时，滚动加载新段落，再点一次「翻译当前页」，确认已有译文没有重复插入。
